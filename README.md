# Prior Art Review Hub 0.1.14

Windows PowerShell 5.1 또는 Windows용 PowerShell 7의 WPF 프로그램입니다. 공유폴더의 JSON이 원본이며 Excel 설치 없이 `.xlsx`와 첨부 ZIP을 만듭니다. AI 검색을 직접 실행하는 도구가 아니라, 대상 건 선정·AI 검색 결과 입력·평가를 관리하는 도구입니다.

최신 배포본: [AIReview-0.1.14.zip](dist/AIReview-0.1.14.zip).

## 로컬 시연

10명 전체 업무 흐름을 검증하려면 다음 명령을 실행합니다. 기존 `DemoData`나 운영 데이터는 변경하지 않고 `TestResults/FullFlow-날짜-고유값`에 새 저장소를 만듭니다. `-IncludeGui`는 실제 WPF 창을 실행해 단계별 화면, 심사관 10명의 평가 화면, AI 담당자 4명의 입력 화면과 관리자 통계를 검사하고 이미지로 남깁니다.

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy RemoteSigned -File .\Tools\Test-FullFlow.ps1 -IncludeGui
```

두 그룹에 심사관을 5명씩 배치하고 그룹마다 ChatGPT·클로드 담당자를 1명씩 배정합니다. 심사관별 2건씩 총 20건을 선정·확정하고, 조사 방식마다 7문헌을 입력한 후 420개 문헌 평가와 세 방식의 품질 순위를 저장합니다. AI 검색 결과는 280문헌, 비교용 선행기술조사는 140문헌입니다. 이름·출원번호·문헌·평가 모두 가상 데이터이며 이 검증에서 실제 AI 검색은 수행하지 않습니다.

| 생성 폴더 | 확인할 단계 |
|---|---|
| `01-SelectionDraft` | 대상 건 선정 · 임시저장된 두 건을 수정하고 선정 확정 |
| `02-SelectionConfirmed` | 선정 확정 · AI 검색 결과 대기, 담당자가 결과 입력 가능 |
| `03-ResultsEntered` | AI 검색 결과 입력 완료 · 심사관이 평가 시작 가능 |
| `04-Evaluated` | 모든 평가 완료 · 전체·그룹·계정별 통계 확인 |

각 폴더의 `User.cmd`에서 **심사과 - 이름**을 선택하고, `Admin.cmd`로 관리자 화면을 엽니다. 단계별 데이터는 독립된 복사본이므로 한 단계에서 수정해도 다른 단계는 바뀌지 않습니다. `안내.txt`에 계정 배정표, `Report.json`에 검증 결과, `Screenshots`에 화면 이미지와 검사 결과를 저장합니다. 프로그램 폴더를 옮겼다면 도구를 다시 실행해 실행 파일을 새로 만드세요. API 업무 검증과 실제 WPF 화면 검증이며, AI 검색 서비스 연결이나 SMB 다중 PC 장애 검증은 포함하지 않습니다.

용도에 맞는 CMD 파일을 실행합니다. 시연 관리자와 가상 참여자가 `DemoData`에 생성됩니다.

| 실행 파일 | 로그인 방식 |
|---|---|
| `관리자용.cmd` | 사용자 선택이나 비밀번호 없이 관리자 화면으로 바로 진입 |
| `일반사용자용.cmd` | 첫 화면의 **심사과 - 이름** 목록에서 본인을 선택 |
| `실행.cmd` | `일반사용자용.cmd`와 동일 |

소스 폴더의 CMD 파일은 로컬 시연 저장소인 `DemoData`를 사용합니다. 실제 출원정보는 시연 저장소에 넣지 마세요. 직접 실행할 때는 다음과 같습니다. 관리자 모드는 명령 끝에 `-AdminMode`를 추가합니다.

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy RemoteSigned -File .\App\Start.ps1 -Demo
```

## 첫 운영 설정과 배포

공용 데이터용 **비어 있는 저장소**를 지정합니다. 초기화는 자동 ID가 부여된 관리자 한 명, `G01`, 조사 방식 세 개와 현재 운영월을 만듭니다. Windows SID를 확인하거나 입력할 필요가 없습니다. 기존 파일이 있으면 중단하며, 시연 표식은 만들지 않습니다. 다음 경로는 예시이고 스크립트가 서버나 공유 권한을 설정하지는 않습니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\Tools\Initialize-Store.ps1 -Root '\\FILESERVER\AIReview\Store' -AdminName '관리자 성명'
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\Tools\Publish-Release.ps1 -Destination '\\FILESERVER\AIReview\Program' -DataRoot '\\FILESERVER\AIReview\Store'
```

배포 폴더에는 `관리자용.cmd`, `일반사용자용.cmd`, `실행.cmd`가 함께 생성됩니다. 관리자는 `관리자용.cmd`, 심사관·AI 담당자는 `일반사용자용.cmd`를 실행합니다. 두 실행 방식은 `Launch.ps1`을 통해 `App\releases\0.1.14`의 같은 프로그램과 위에서 지정한 **같은 공용 저장소**를 사용합니다. `실행.cmd`는 일반사용자용 실행 진입점입니다. 관리자 실행은 Windows의 **관리자 권한으로 실행**이나 UAC 승격을 요구하지 않습니다.

초기화에서 만든 관리자 계정으로 관리자 화면에 바로 진입하며, 활성 관리자 계정이 없으면 안내 메시지를 표시하고 종료합니다. 새 저장소에서는 위의 초기화 명령으로 첫 관리자를 생성합니다. 직접 실행할 때는 다음과 같습니다.

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy RemoteSigned -File .\App\Start.ps1 -DataRoot '\\FILESERVER\AIReview\Store'
# 관리자 화면으로 바로 실행:
powershell.exe -NoProfile -STA -ExecutionPolicy RemoteSigned -File .\App\Start.ps1 -DataRoot '\\FILESERVER\AIReview\Store' -AdminMode
```

실행 파일은 해당 PowerShell 프로세스에만 `RemoteSigned`를 적용하며 PC의 영구 실행 정책을 변경하지 않습니다. 기관의 `MachinePolicy`·`UserPolicy`와 스크립트 서명 기준은 계속 우선합니다. 배포 스크립트는 기존 버전과 실행 진입점을 덮어쓰지 않으므로 업데이트 때는 새 배포 폴더에서 검증한 뒤 바로가기를 전환합니다. 초기화가 중간 실패하면 기록을 보존하고 새 빈 폴더에 초기화하세요.

## 스크립트를 실행할 수 없다는 오류

0.1.1부터 `실행.cmd`가 이 실행에만 `RemoteSigned`를 지정합니다. 기존 파일을 쓰는 경우 프로젝트 폴더에서 위의 직접 실행 명령을 사용하세요. [Microsoft 실행 정책 설명](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies?view=powershell-5.1)

GitHub ZIP을 내려받았다면 ZIP 파일의 **속성 → 차단 해제 → 적용** 후 새 폴더에 압축을 푸세요. 이미 압축을 풀었다면, 내용을 신뢰하는 이 프로젝트 폴더에서 아래 명령으로 프로그램 파일만 차단 해제할 수 있습니다.

```powershell
Get-ChildItem -LiteralPath .\App,.\Tools,.\Tests -Recurse -File |
    Where-Object { $_.Extension -in '.ps1', '.psm1' } |
    Unblock-File
```

배포 폴더의 `Launch.ps1`에도 다운로드 표시가 있다면 `Unblock-File -LiteralPath .\Launch.ps1`을 적용합니다. 이 명령은 파일의 다운로드 표시만 제거합니다. [Microsoft Unblock-File 설명](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/unblock-file?view=powershell-5.1)

계속 차단되면 다음 명령으로 정책을 확인하세요. `MachinePolicy` 또는 `UserPolicy`가 `Restricted`·`AllSigned`이면 전산 담당자가 허용·서명한 배포본이 필요합니다. 일부 공유폴더 경로가 인터넷 영역으로 분류되는 경우도 확인해야 합니다.

```powershell
powershell.exe -NoProfile -Command "Get-ExecutionPolicy -List"
```

## 사용자 등록과 로그인

관리자로 로그인한 뒤 **운영 관리 → 사용자**에서 작업에 맞는 탭을 선택합니다.

- **신규 사용자 등록**: 빈 양식에 성명·심사국·심사과·역할·활성 여부를 입력하고 **사용자 등록**을 누릅니다. 사용자 ID와 내부 식별값은 자동으로 부여됩니다. 등록이 끝나면 완료된 사용자 이름을 안내하고 양식을 비워 다음 사용자를 바로 등록할 수 있습니다.
- **기존 사용자 관리**: **관리할 사용자** 목록에서 대상을 선택하면 정보가 바로 표시됩니다. 소속·역할·활성 여부 등을 수정하고 **변경사항 저장**을 누릅니다. 신규 등록 직후 이 탭으로 이동하면 방금 등록한 사용자가 선택됩니다. 비활성 사용자도 목록에서 찾아 수정하거나 다시 활성화할 수 있습니다.

신규 등록 화면에는 기존 사용자 선택 목록을 표시하지 않으며, 수정하던 사용자의 정보가 신규 양식에 남지 않습니다. 저장하지 않은 입력이 있으면 탭을 바꾸기 전에 확인합니다. 심사국과 심사과는 기존 값을 드롭다운에서 고르거나 새 이름을 직접 입력합니다. 두 항목은 비워 둘 수도 있습니다.

관리자는 **관리자용.cmd**를 실행하면 사용자 선택이나 비밀번호 없이 관리자 화면에 바로 진입합니다. 심사관·AI 담당자는 **일반사용자용.cmd** 또는 **실행.cmd**를 실행한 뒤 첫 화면의 **심사과 - 이름** 목록에서 본인을 선택합니다. 같은 PC에서도 서로 다른 사용자를 선택할 수 있습니다. 이 선택은 업무 작성자를 정하는 간편 로그인이며 Windows 계정 인증과 연결하지 않습니다.

일반사용자용 로그인에는 활성 심사관·AI 담당자를 표시하고, 메뉴와 업무 범위는 선택한 사용자의 역할·월별 배정에 따라 정합니다. 관리자와 심사관 역할을 함께 가진 사용자를 선택해도 일반사용자용 실행에서는 관리자 메뉴를 제공하지 않습니다. 관리자 역할만 가진 사용자는 일반사용자용 로그인 목록에 표시하지 않습니다.

역할은 `admin`, `examiner`, `ai`를 중복 부여할 수 있습니다. 전출자는 삭제 대신 비활성화하여 과거 기록을 보존합니다. 이전 버전의 사용자 ID와 SID도 그대로 유지하므로 기존 사용자·검색 결과 입력·평가 연결을 다시 만들 필요가 없습니다.

## 그룹·조사 방식·월 운영 관리

**운영 관리** 상단에서 사용자·그룹·조사 방식·월 운영을 드롭다운으로 선택합니다. 사용자는 **신규 사용자 등록 / 기존 사용자 관리** 탭에서 관리합니다. 그룹·조사 방식·월 운영의 기존 항목은 대상 목록에서 선택하면 바로 조회되고, 새 항목은 **신규 그룹·신규 조사 방식·신규 월** 버튼으로 만듭니다. 폼을 작성한 뒤 **변경사항 저장**을 누릅니다. 원본 JSON이나 사용자 식별번호를 직접 편집할 필요가 없습니다. 사용자, 그룹·조사 방식, 월 운영 순으로 준비하면 됩니다.

그룹은 이름과 활성 여부를, 조사 방식은 이름·유형·활성 여부를 설정합니다. 유형은 드롭다운에서 고릅니다. 기본 조사 방식은 선행기술조사, ChatGPT, 클로드입니다. 일반 조사 결과는 관리자용 실행의 AI 담당 업무에서 조사 방식을 선택해 대리 등록합니다.

새 운영월은 연도와 월 드롭다운으로 정합니다. **참여 심사관**에서 심사관·그룹을, **AI 담당 배정**에서 AI 담당자·그룹·조사 방식을 드롭다운으로 골라 행을 추가합니다. 사용하지 않는 행은 삭제합니다. 이번 달 비교할 조사 방식은 목록에서 여러 개 선택합니다. 이름으로 선택하면 내부 식별번호가 자동으로 연결됩니다. 초기 관리자는 첫 운영월의 `G01` 참여자 및 두 AI 담당자로 등록됩니다. 새 사용자는 필요한 운영월에 참여자로 추가하고, AI 담당자이면 담당 조사 방식도 배정합니다.

제출·검색 결과 입력·평가 기한은 달력에서 선택하며, 선택 날짜의 끝인 23시 59분 59초까지로 적용합니다. 기한 공란은 제한 없음입니다. 심사관별 제출 건수 상한은 드롭다운에서 선택하거나 직접 입력하고, 0은 건수 제한 없음입니다. 월마다 참여자·AI 배정을 별도로 보존합니다. 저장한 새 운영월은 화면 목록에 바로 반영됩니다. 월 마감·재개방은 전용 버튼을 사용합니다. 별도 사유 입력은 필요하지 않습니다.

## 일상 업무

관리자용 실행의 첫 화면은 **통계·현황**입니다. 상단 운영월을 바꾸면 해당 월의 자료를 다시 집계하고, **새로 고침**으로 다른 사용자가 저장한 결과를 반영합니다. 전체 통계는 선택한 운영월의 전체 그룹을 뜻합니다.

- 요약 카드에서 참여 심사관·미선정 인원, 확정 출원, AI 결과 입력 완료율, 평가 완료율을 확인합니다. 미선정에는 임시저장 중인 참여자도 포함됩니다. 취소된 출원과 미확정 초안은 출원·검색 결과 입력·평가 건수에서 제외합니다.
- **그룹별 통계**에서 그룹을 클릭하면 해당 그룹의 **계정별 현황**으로 이동합니다. 계정을 클릭하면 본인의 **출원별 현황**으로 이동합니다. 위의 그룹·계정 드롭다운으로도 즉시 좁혀 볼 수 있으며 **전체 보기**로 필터를 초기화합니다.
- 계정별 현황에는 미선정·미참여·비활성 계정도 표시합니다. 본인 출원의 평가 진행과 **담당 입력 완료 / 대상**을 구분합니다. 담당 결과 입력은 선택한 월의 현재 AI 배정을 기준으로 출원 × 조사 방식 단위로 셉니다.
- **조사 방식별 통계**는 선행기술조사와 AI 방식의 검색 결과 입력 수, 문헌 수, 평균 점수, 인용률, 1위 횟수를 표시합니다. 평균은 점수가 입력된 문헌만, 인용률은 O/X를 선택한 문헌만 분모로 사용합니다. 실제 0점·X도 집계하며 미입력은 제외합니다. 검색 결과가 수정되면 해당 방식의 이전 문헌 평가와 재확인 필요 건의 품질 순위는 통계에서 제외합니다.
- **현재 통계 엑셀 다운로드**는 화면의 그룹·계정 범위와 동일한 집계 결과 및 조회 기준을 문서 폴더 `AI검색평가`에 저장합니다. 파일은 그룹별·계정별·출원별·조사 방식별·조회 기준의 다섯 시트로 구성됩니다.

AI 결과 입력 완료는 해당 월 AI 검색 결과가 모두 입력된 출원을 뜻합니다. 평가 완료는 선행기술조사를 포함한 모든 비교 방식의 문헌 평가와 품질 순위가 완료되고 재확인이 필요하지 않은 출원입니다. 빈 운영월이나 평가 입력이 없으면 0건 또는 `—`로 표시합니다. 읽을 수 없는 원본이 있으면 오류를 안내하고 집계 결과를 표시하지 않습니다. 통계는 출원별로 저장 잠금을 잡아 읽으며, 화면에 표시된 집계 시각을 기준으로 한 조회 결과입니다.

화면 상단에서 **내 심사 업무**, **AI 담당 업무**, **운영 관리**를 구분합니다. 사용자 역할에 필요한 업무만 표시합니다.

| 사용자 | 표시되는 업무 | 출원 목록의 범위 |
|---|---|---|
| 일반 심사관 | 내 심사 업무 | 본인이 선정한 출원 |
| AI 담당자 겸 심사관 | 내 심사 업무, AI 담당 업무 | 개인 업무에서는 본인 출원, AI 담당 업무에서는 담당 그룹의 배정 조사 방식에 해당하는 출원 |
| 관리자 | 통계·현황, 운영 관리 및 역할에 따른 내 심사 업무·AI 담당 업무 | 통계는 선택한 운영월 전체 및 그룹·계정별 범위, 나머지는 선택한 업무의 범위 |

일반 심사관에게는 **AI 검색 결과 입력**을 표시하지 않습니다. AI 담당자가 자신의 출원을 선정하거나 평가할 때는 **내 심사 업무**를 사용하고, 담당 그룹의 AI 검색 결과를 입력할 때는 **AI 담당 업무**로 이동합니다. 두 업무를 바꾸면 출원 목록과 입력 화면도 해당 업무의 범위로 바뀝니다.

**내 심사 업무**는 운영월별 선정 확정 여부에 따라 화면이 바뀝니다. 일반사용자용 실행에 적용되며 AI 담당자의 개인 심사 업무에도 같은 흐름을 사용합니다.

1. **대상 건 선정 전**에는 **1. 대상 건 선정** 화면만 표시합니다. 출원번호와 CPC를 입력하고 목록에 추가하거나 `출원번호<TAB>CPC`를 여러 줄 붙여 넣습니다. **임시저장**하면 해당 운영월의 초안으로 보관하여 다음 로그인에서도 이어서 수정할 수 있습니다. 초안은 AI 담당자의 대상 건 목록과 평가·다운로드 목록에 공개하지 않습니다. CPC는 선택 항목입니다.
2. 목록을 검토한 뒤 **선정 확정**을 누르면 전체 목록의 형식·중복·제출 상한을 검사하고 AI 담당자의 검색 대상 목록에 표시합니다. 확정 후에는 **2. AI 검색 결과 평가** 화면으로 자동 이동합니다. 왼쪽 **내 평가 대상 건**에 출원번호와 **대기 중 / 입력 완료**를 표시하며, 건을 클릭하면 오른쪽 평가를 바로 불러옵니다. 이번 달 비교 대상 AI 검색 결과가 모두 입력되면 입력 완료이며, 일부만 도착하거나 초안만 있으면 대기 중입니다.
3. 품질 순위에는 **선행기술조사와 해당 월 AI 조사 방식**을 함께 표시합니다. 검색 결과 입력 전인 방식은 대기 중으로 표시하고 순위 선택을 잠급니다. 선행기술조사도 월 비교 방식에 포함하고 관리자 화면에서 결과를 등록하면 순위를 입력할 수 있습니다. **문헌별 평가**에는 조사 방식·문헌·점수(0~5점)·인용여부(O/X)·비고를 표시하며 품질 순위보다 높게 배치했습니다. 점수·인용 여부·순위는 드롭다운으로, 비고는 셀을 눌러 입력한 뒤 **평가 저장**을 누릅니다. 미선택과 0점·X는 구분됩니다. 검색 결과가 수정되면 평가를 다시 확인해야 합니다.

이전 버전에서 이미 제출한 건은 확정된 대상 건으로 이어받아 바로 평가 화면을 엽니다. 새 운영월에는 다시 대상 건 선정부터 시작합니다. 확정한 월의 목록은 일반사용자 화면에서 다시 편집하지 않습니다. 관리자용 실행의 기존 직접 등록·취소 기능은 유지합니다. 운영월 전환·새로 고침·종료 때 저장하지 않은 초안 변경이 있으면 확인하고, 임시저장한 내용은 운영월별로 보존합니다.

평가 표는 창을 줄여도 품질 순위 152, 문헌별 평가 300 이상의 높이를 유지합니다(WPF 화면 단위). 기본 3개 조사 방식이 순위 표에 함께 표시되고, 문헌 표에는 약 6행을 볼 공간을 확보합니다. 창이 작으면 본문을 아래로 스크롤하여 문헌 표 전체를 확인할 수 있으며 **평가 저장** 버튼은 화면 아래에 고정됩니다. 목록이 화면 밖에 걸쳐 있으면 목록 위에서도 마우스 휠로 본문을 이동할 수 있습니다. 왼쪽 출원 목록·대상 건 목록·AI 결과 입력·월 운영의 참여자·담당자 표도 최소 높이를 적용했습니다. 시작 창은 작업표시줄을 제외한 화면 크기에 맞춰 열립니다.

다른 출원을 선택하면 평가·결과 조회·AI 결과 입력 본문이 맨 위에서 열립니다. 같은 출원의 평가를 저장하거나 검색 결과 저장 후 다시 불러올 때는 현재 작업 위치를 유지합니다.

**AI 담당 업무**에서는 담당 대상 건 목록에서 출원을 선택한 뒤 **AI 검색 결과 입력**에서 배정받은 조사 방식을 고릅니다. 선택한 방식의 결과가 바로 표시됩니다. 결과 문헌은 **출원번호만** 입력하거나 한 줄에 하나씩 붙여 넣습니다. 문헌명·유형 입력과 파일 첨부 없이 방식별 최대 7건을 등록합니다. 임시저장한 결과는 심사관에게 공개하지 않습니다. **AI 검색 결과 입력 완료**를 누르면 문헌이 심사관에게 공개됩니다. 수정할 때도 내용을 고친 뒤 같은 버튼으로 저장하면 됩니다. 수정 사유, 검색했으나 결과 없음, 버전 번호와 이력 조회 기능은 화면에서 제공하지 않습니다. 공개할 문헌번호는 한 건 이상 입력해야 하며, 문헌을 찾지 못했으면 입력하지 않은 채로 둘 수 있습니다. 저장 후 선택 출원의 결과를 자동으로 갱신합니다.

운영월을 드롭다운에서 바꾸면 현재 업무의 목록과 상세 정보를 자동으로 갱신합니다. 좌측 검색창에서는 출원번호·CPC·심사관·소속으로 찾을 수 있습니다. **엑셀 · 첨부파일 다운로드**에서 **선택 출원 다운로드**는 선택한 한 건을, **이번 달 엑셀 다운로드**와 **이번 달 엑셀 + 첨부 ZIP**은 현재 운영월·업무 범위의 전체 자료를 문서 폴더 `AI검색평가`에 저장합니다. Excel은 출원별 현황·선행기술 목록·품질 순위·문헌별 평가 네 시트이며 심사국·심사과·CPC도 표시합니다. 버전 번호 열은 포함하지 않습니다. ZIP에는 Excel을 담고, 이전에 등록한 첨부문헌이 있으면 함께 포함합니다.

제출 당시 심사국·심사과와 CPC를 보관하므로 이후 사용자 소속을 바꿔도 기존 출원의 소속은 바뀌지 않습니다. 이전 데이터에 새 항목이 없으면 공란으로 표시합니다. 기존 검색 결과의 문헌명 등 보관 정보도 유지합니다.

저장 충돌이 나면 입력내용을 보존한 채 최신 내용을 다시 불러오세요. 저장 직후 연결이 끊긴 경우 같은 입력으로 재시도하면 저장 요청 ID를 확인합니다. 같은 ID에 다른 내용을 보내면 거절합니다. 확정 JSON이나 `.lock` 파일은 프로그램이 관리합니다.

사용자는 버전을 관리할 필요가 없습니다. 기존 자료와의 호환성, 동시 저장 충돌 방지, 검색 결과 변경에 따른 평가 확인을 위해 내부 저장 기록은 `revisions/000001.json`부터 자동으로 보관합니다. 이전 이력과 과거 결과 없음 자료도 삭제하지 않습니다. 확정 전 임시파일은 조회하지 않습니다. 선정 확정은 개별 제출정보를 준비한 뒤 월별 선정 기록 한 번으로 전체를 공개합니다. 중간 실패로 준비된 제출정보는 목록·검색 결과 입력·평가에서 제외하며 동일 요청으로 재시도할 수 있습니다. 잠금은 파일의 존재 여부가 아니라 열려 있는 파일 핸들로 판정합니다.

배포 프로그램은 참여자에게 읽기·실행 권한을, 공유 저장소는 참여자의 실제 Windows 계정에 프로그램 운영에 필요한 읽기·쓰기 권한을 부여합니다. 사용자 선택은 프로그램 안의 작성자와 업무 범위를 정하고, 파일서버 접근은 접속 중인 Windows 계정의 권한을 사용합니다. 선택한 사용자에 맞춰 NTFS 권한이 바뀌지는 않습니다. 별도 백업은 백업 운영 계정으로 관리합니다.

## 점검과 백업

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy RemoteSigned -File .\Tests\Run-All.ps1
pwsh.exe -NoProfile -STA -ExecutionPolicy RemoteSigned -File .\Tests\Run-All.ps1
# 실제 창을 열어 화면 동작까지 검사하려면 추가:
powershell.exe -NoProfile -STA -ExecutionPolicy RemoteSigned -File .\Tests\Run-All.ps1 -IncludeGui
```

로컬 테스트는 별도 프로세스의 동시 저장·오래된 버전 거절·동일 요청 재시도·잠금 해제·JSON 손상·로그인 선택·업무 규칙·내보내기·운영 초기화와 배포를 검사합니다. 대상 건 초안의 재접속 복원·월별 분리·확정 중단 후 재시도·검색 결과 입력 상태도 검사합니다. 기본 검증은 창을 표시하지 않으며 `-IncludeGui`가 실제 창 실행 검증을 추가합니다. 실제 SMB/NAS에서 두 PC 동시 사용과 네트워크 단절 중 저장·복구는 해당 환경에서 확인해야 합니다.

화면 검증에는 1480×940, 1366×728, 1220×760, 1100×640 창에서 역할별 평가 화면, 21개 문헌의 마지막 행 접근, 최소 표 높이, 고정된 저장 버튼과 휠 스크롤을 검사하는 `Tests/Gui.Layout.Tests.ps1`도 포함됩니다.

버전 이력과 별도로 데이터·첨부·월 설정을 함께 백업하고, 월 마감본을 보관하세요. 파일서버 스냅샷과 별도 백업을 사용하고 출원 한 건의 실제 복구를 시험합니다.

관리자 문헌 일괄 등록, 진행 중인 건의 그룹 이관, 조사 방식 간 동일 문헌·인용 불일치 자동 안내는 아직 포함하지 않습니다.
